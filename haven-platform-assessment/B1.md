# B1 - The Glacier cost gotcha

(Prices below are approximate us-east-1 list prices; verify against the current AWS pricing page.)

## Actual cost impact

The lifecycle rule uses `storage_class = "GLACIER"` (Glacier Flexible Retrieval), which has a
**90-day minimum storage duration**. A photo archived on day 30 and deleted on day 40 has been
there 10 days; S3 bills the remaining **80 days** as an early-deletion charge, prorated, as if it
had stayed. Per GB that's about 80/30 months x ~$0.0036/GB-month = **~$0.0096/GB**, charged at
the moment of deletion, on top of the ~10 days already paid and the 30 days in Standard
($0.023/GB-month) before transition. Also paid regardless: the lifecycle transition request fee
(~$0.03 per 1,000 objects) and per-object metadata overhead (~40 KB per object in Glacier), which
hurts for many small photos.

Net effect: the "saving" from archiving is wiped out (and then some) for every object deleted
before day 120. Because the deletion is a legal/user obligation, we can't avoid paying; and
**delaying the delete doesn't help** - the 90-day minimum is paid in full either way, deferring
within the 30-day deletion window only delays when the bill lands. It shows up as the
`EarlyDelete-ByteHrs` usage type, not as an obvious line item, so it silently exceeds budget.

## Redesign

1. **Don't use a minimum-duration class for objects that may still be deleted.** Transition to
   `INTELLIGENT_TIERING` at day 30 instead: no minimum storage duration and no early-deletion
   fee, automatic cheaper tiers for cold data (optionally enable the Archive Access tiers),
   small monitoring fee per object (objects < 128 KB aren't monitored/tiered - pair with a size
   filter for tiny thumbnails). 
2. **Or move the Glacier transition later**, past the point where deletion requests are rare
   (pick the day from data: e.g. a day-120+ cut-off, or after listing is sold and closed), so a
   delete lands after the 90 days are already served.
3. **Scope the rule.** Today it has no filter and applies to the whole bucket. Add a filter
   (prefix, or a `listing_status=sold` object tag) so only sold-listing photos transition.
4. **Make the cost visible.** Budget alarm / Cost Explorer or CUR filter on `EarlyDelete`
   usage types, S3 Storage Lens; tag buckets with `landlord_account_id` so the charge maps to
   the billing unit; track deletion-request rate vs archive age.
5. Add `abort_incomplete_multipart_upload` and noncurrent-version expiry so leftovers don't add
   quiet cost.

Sketch:

```hcl
rule {
  id     = "tier-sold-listing-photos"
  status = "Enabled"
  filter { tag { key = "listing_status" value = "sold" } }
  transition { days = 30 storage_class = "INTELLIGENT_TIERING" }
}
```
